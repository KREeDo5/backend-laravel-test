# Постановка задачи
*Название проекта*
	- API и Админка для мобильного приложения "Блог"
*Описание*
	- Приложение блог, которое позволяет авторизоваться и/или зарегистрироваться пользователям, а также опубликовать запись в блог, и получить публикации из блога.
*Платформа*
	- PHP / Laravel
*Формат ответов API* 
	- JSON
*Система подключения зависимостей и библиотек:* 
	- Composer
АПИ предоставляет серверные методы для реализации этого сценария
*Архитектура* 
	- MVC
*База Данных* 
	- MySQL 8.0+ (Использование миграций для создания таблиц и изменения таблиц БД ОБЯЗАТЕЛЬНО)

# Сценарий работы в Мобильном приложении
- Пользователь регистрируется или авторизуется в приложении
- Может просмотреть общую ленту публикаций в системе
- Может отправить свою публикацию в блог
- Может просмотреть список своих публикаций


# Возможности API

## Апи для авторизации пользователя

`POST` запрос

- API должно принимать входящие параметры:

  - `email` - Email

  - `password` - Пароль

- Проверять, есть ли в БД пользователь с таким email и паролем

  - Если есть – выдавать ключ доступа `accessToken`

  - Если нет – возвращать ошибку

### Технические особенности

- `accessToken` создать с помощью метода `$model→createToken()`

- `accessToken` в дальнейшем будет передаваться в заголовке каждого запроса для идентификации пользователя

## Апи для регистрации пользователя

`POST` запрос

- API должно принимать входящие параметры

  - `name` - Имя

  - `email` - Email

  - `password` - Пароль

- Проверять, есть ли в БД пользователь с таким email и паролем

  - Если нет – регистрировать пользователя и возвращать `access_token`

  - Если есть – возвращать ошибку

## API. Апи для публикации поста в блог

`POST` запрос

- API должно принимать входящие параметры:

  - Заголовки

    - `Authorization: Bearer <accessToken>`

  - Тело запроса

    - `title` - название публикации

    - `text` - текст публикации

- Проверять существование пользователя по токену

- Находить пользователя и публиковать пост в блог от его имени

## API. Апи для получения всех публикаций в системе

`GET` запрос

- API работает порционно, т.е. за раз не должны возвращаться все записи в таблице, а только небольшая порция

- API должно принимать входящие параметры:

  - сортировка по дате или по названию/заголовку

  - `limit` - сколько записей вернуть. Необязательное поле

  - `offset` - сколько записей ранее уже было загружено. Необязательное поле

- Возвращает список сериализованных публикаций

### Доп. требование (обязательно для `middle` разработчиков)

- фильтрация по дате (от, до)

- поддержка нескольких вариантов сортировок

  - по дате

  - по названию/заголовку

## API. Апи для получения моих публикаций

`GET` запрос

- По аналогии со списком всех публикаций

### Доп. требование (обязательно для `middle` разработчиков)

- фильтрация по дате (от, до)

- поддержка нескольких вариантов сортировок

  - по дате

  - по названию/заголовку

## Доп. требование (обязательно для `middle` разработчиков) для всех контроллеров API:

- Построить работу через “тонкие” контроллеры

  - Всю бизнес-логику методов API, описанных выше, выносить в отдельные классы

    - Туда же обработку входящих параметров метода API

    - Туда же работу с ошибками

  - Логику по отдаче и обработке данных помещать в сам класс, а не контроллер
